## ⭐ Featured Projects

> Each project has a README covering architecture, setup, evaluation and limitations.

### 🧠 1. Enterprise AI Knowledge Assistant: *Generative AI / RAG*
**Problem:** Employees waste time searching policies and documents, and the answers they need must be accurate, cited and permission-aware.

- Document upload and ingestion with **Docling**, plus **hybrid search** (vector + keyword) on **PostgreSQL + pgvector**
- **Cross-encoder reranking**, **cited streaming answers** and conversation memory
- **JWT authentication** with **role- and department-based access control**
- **LangGraph agent tools** with user confirmation, prompt-injection safeguards and a cost dashboard
- Evaluation pipeline built on **Ragas, promptfoo and Langfuse**, run against a golden set of 50+ questions on 50+ policy documents
- **Evaluation targets:** faithfulness ≥ 0.85 · answer relevance ≥ 0.80 · retrieval hit@5 ≥ 80% · attack success < 10%

`FastAPI` `PostgreSQL` `pgvector` `Docling` `LangGraph` `LLM APIs` `JWT` `Ragas` `promptfoo` `Langfuse` `Docker Compose`

---

### 🎫 2. Production AI Support Ticket Triage Platform: *Production AI Application*
**Problem:** Support teams need tickets categorised, prioritised and routed instantly, along with good draft replies.

- Tickets REST API with **RBAC**, an **ML classifier served from the MLflow model registry**, and **LLM + RAG draft replies with citations**
- **Background worker**, user feedback loop and **drift monitoring with Evidently**
- **CI/CD with GitHub Actions**, with automated deployment to **AWS (ECR, ECS / App Runner, RDS)** on merge
- Monitoring dashboards and alerts with **Prometheus/Grafana or CloudWatch**
- Quality bar: **80%+ test coverage**, integration tests, **Locust load tests** (throughput and p95 latency) and an error-spike drill

`FastAPI` `PostgreSQL` `SQLAlchemy` `Alembic` `JWT` `pytest` `Docker` `GitHub Actions` `MLflow` `AWS` `Evidently` `Locust`

---

### 🚦 3. Smart Traffic Monitoring System: *Computer Vision*
**Problem:** City planners need automated vehicle counts, vehicle classes, speeds and congestion levels from camera feeds.

- Classical OpenCV baseline, then a **fine-tuned YOLO detector** for local vehicle types
- **ByteTrack** multi-object tracking, **directional counting**, **speed estimation** and congestion metrics
- Results stored in **PostgreSQL** and shown on a **Streamlit dashboard**, with annotated output videos
- Evaluated with mAP on a validation set, counts checked within 10% of manual counts, and FPS benchmarks

`OpenCV` `Ultralytics YOLO` `ByteTrack` `Supervision` `PyTorch` `PostgreSQL` `Streamlit`
